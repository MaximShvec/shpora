Короткая шпаргалка перед собесом

Темы middle frontend React. Каждая карточка — 3–5 простых предложений. Жирным выделены слова, которые стоит произнести вслух. Есть режим теста: пишешь ответ своими словами и сверяешь с эталоном.

Это не учебник и не «правильный ответ на 10 минут». Цель — быстро освежить картинку в голове: что это, зачем это, чем одно отличается от другого.

01 Типы данных в JS

В JavaScript есть примитивы: string, number, boolean, null, undefined, bigint, symbol. Всё остальное — object: объекты, массивы, функции, даты. Примитив копируется по значению, объект — по ссылке: две переменные могут смотреть на один и тот же объект в памяти.

typeof null странно вернёт "object" — это старый баг языка, его просто помнят. Массив проверяют через Array.isArray, а не typeof. На собесе часто дают пару значений и спрашивают, что вернёт typeof.

02 var, let, const

var живёт во всей функции, даже если написан внутри if. Он всплывает и сначала равен undefined, его можно объявить дважды. В нестрогом режиме глобальный var ещё и становится полем window — поэтому его почти не используют.

let и const живут в блоке { }. До своей строки они уже «заняты», но доступа нет — это временная мёртвая зона. Повторно объявить то же имя в одном блоке нельзя. const запрещает подменить саму переменную: число или строку не переназначишь. Если внутри объект — поля менять можно, заморожена только ссылка.

В работе по умолчанию берут const. let — когда значение реально переназначаешь: счётчик, флаг, накопленный результат. На собесе часто дают код с var в цикле или обращение к let выше объявления.

Вопрос / ответ

В: Почему const не защищает объект от изменений?

О: const держит ссылку. Саму переменную не переприсвоишь, а поля внутри объекта — можно.

03 == и ===

=== сравнивает и значение, и тип: 1 === "1" это false. == сначала приводит типы, поэтому 1 == "1" true, а null == undefined тоже true. Из-за этих сюрпризов в работе почти всегда пишут строгое равенство.

Отдельная ловушка: NaN === NaN — false, проверяют через Number.isNaN. На собесе могут спросить таблицу: false == 0, "" == 0, null == 0. Последнее — false, null дружит через == только с undefined.

04 Области видимости

Область видимости — где переменную видно. Есть глобальная, функциональная и блочная. Вложенная функция видит переменные снаружи, наоборот — нет. Движок ищет имя сначала рядом, потом выше, пока не дойдёт до глобальной области.

Если не нашёл — будет ошибка is not defined. Это не то же самое, что undefined: второе значит «переменная есть, значения нет». Модули ES6 имеют свою область: то, что не экспортировал, снаружи не видно.

05 Всплытие (hoisting)

Всплытие — движок сначала регистрирует объявления, потом выполняет код сверху вниз. Поэтому кажется, будто объявления «поднялись». У var поднимается имя со значением undefined: переменная уже есть, значения ещё нет. У function declaration поднимается вся функция — её реально можно вызвать выше по файлу.

У let, const и class имя тоже резервируется, но до своей строки доступ закрыт: будет ошибка, не undefined. Function expression и стрелка — это просто переменные. Если они на const, выше вызова их ещё нет. На собесе почти всегда дают «что выведется», если функцию или var трогают до объявления.

Вопрос / ответ

В: Почему function declaration можно вызвать выше, а стрелку нельзя?

О: Declaration всплывает целиком. Стрелка живёт как переменная: до своей строки её ещё нет.

06 Замыкания

Замыкание — функция помнит переменные той области, где её создали, даже если снаружи эта область уже закончилась. Это не магия и не копия: функция держит живую ссылку на окружение. Поменял переменную позже — все замкнутые функции видят новое значение.

Так делают счётчик, «приватные» данные модуля и колбэки, которым нужны данные снаружи. Память тоже держится: пока функция жива, живы и замкнутые переменные. Классическая ловушка: цикл с var и setTimeout — все колбэки смотрят на одно i. С let у каждой итерации своя переменная.

Вопрос / ответ

В: Замыкание копирует значение переменной?

О: Нет. Это ссылка на окружение. Изменил переменную — подписчики видят уже новое.

07 this в JS

this — кто вызвал функцию, а не где её написали. У обычной функции this зависит от вызова: obj.method() даст obj, голый вызов в строгом режиме — undefined. У стрелки своего this нет: она берёт его снаружи и его не перебить вызовом.

В обработчике DOM у обычной функции this — элемент, у стрелки — уже нет. В классах методы лучше вешать стрелкой или биндить, иначе this потеряется в колбэке. На React-собесе this почти не мучают, но база нужна, если дадут чистый JS.

08 call, apply, bind

Три способа явно сказать функции: «вот твой this». call(this, a, b) вызывает сразу, аргументы списком. apply(this, [a, b]) то же, но аргументы массивом. bind(this) не вызывает, а возвращает новую функцию с пришитым this.

bind ещё умеет заранее подставить часть аргументов — это частичное применение. Стрелку биндить бессмысленно: this у неё и так лексический. Сейчас чаще пишут стрелки и не трогают bind, но вопрос любят как проверку базы.

09 Прототипы

У объекта есть скрытая ссылка [[Prototype]]. Её смотрят через Object.getPrototypeOf, старое имя — __proto__. Нет своего свойства — JS идёт по цепочке прототипов, пока не найдёт имя или не упрётся в null. Так у всех массивов появляется map: метод один, лежит на Array.prototype, а не копируется в каждый массив.

class — сахар над этой схемой: методы класса живут на прототипе и шарятся, поля экземпляра — свои. hasOwn спрашивает «это моё поле», оператор in смотрит ещё и вверх по цепочке. На middle ждут цепочку и разницу: своё свойство vs унаследованное.

Вопрос / ответ

В: Где лежит метод массива map?

О: На Array.prototype. Массив находит его по цепочке, это не копия внутри каждого массива.

10 Рекурсия

Рекурсия — функция вызывает сама себя, пока не дойдёт до базового случая. Без него будет бесконечный вызов и переполнение стека. Удобно для деревьев, вложенных комментариев, обхода папок, глубокого клона.

Каждый вызов занимает кадр в стеке, поэтому очень глубокая рекурсия опасна. Иногда её заменяют циклом и своей стопкой. На собесе часто просят факториал или обход дерева: важно сначала назвать условие выхода, потом шаг «уменьшения задачи».

11 Event loop

JS однопоточный: одновременно крутится один кусок кода в call stack. Когда стек пуст, event loop забирает задачи из очередей. Сначала все микротаски (Promise.then, queueMicrotask, MutationObserver), потом одна макротаска (setTimeout, setInterval, события UI), и снова микротаски.

Поэтому промис срабатывает раньше setTimeout(fn, 0). Тяжёлый цикл без пауз замораживает страницу: цикл событий не доходит до отрисовки. async/await — тот же промис: после await продолжение функции идёт как микротаска.

1. Синхронный код → call stack
2. Очередь микротасков: Promise.then / await
3. Одна макротаска: setTimeout / click
4. Браузер может отрисовать кадр и начать сначала

12 Промисы и async/await

Promise — коробка на будущий результат. Состояния: pending, fulfilled, rejected. Один промис меняет состояние один раз. then — успех, catch — ошибка, finally — в любом случае. Цепочка then возвращает новый промис, поэтому ошибки можно поймать внизу одним catch.

Promise.all ждёт все и падает от первой ошибки. allSettled дождётся всех, даже если кто-то упал. race берёт первый финиш, any — первый успех. async функция всегда возвращает промис. await ставит паузу и разворачивает результат, ошибки ловят try/catch. Несколько await подряд — очередь. Параллель — через Promise.all.

Вопрос / ответ

В: Почему несколько await подряд медленнее, чем Promise.all?

О: await ждёт по одному. all запускает все сразу и ждёт общий финиш.

13 Всплытие и погружение событий

Клик идёт в три фазы. Сначала погружение (capturing): от window вниз к цели. Потом сама цель. Потом всплытие (bubbling): обратно наверх. По умолчанию слушатель сидит на всплытии. Третий аргумент true в addEventListener включает погружение.

event.target — кто кликнут, currentTarget — на ком висит слушатель. stopPropagation обрывает дальнейший путь по дереву. preventDefault не трогает путь, а отменяет действие браузера: переход по ссылке, отправку формы. Это разные кнопки, их часто путают. На собесе рисуют вложенные div и спрашивают порядок вызовов.

window → html → body → … → цель (погружение)
цель
цель → … → body → html → window (всплытие)
Вопрос / ответ

В: Чем stopPropagation отличается от preventDefault?

О: Первый стопит путь события по дереву. Второй — действие браузера, например переход по ссылке.

14 Делегирование событий

Делегирование — один слушатель на родителе ловит клики детей за счёт всплытия. Смотришь event.target и понимаешь, по какой кнопке кликнули. Не нужно вешать обработчик на каждую строку списка.

Это экономит память и само работает для элементов, которые появились позже. В React часто не думаешь об этом: обработчик и так на родителе в JSX. Но вопрос про «зачем вешать на ul, а не на каждый li» всё ещё живой.

15 Копирование объектов

Присвоение obj2 = obj1 копирует ссылку: два имени, один объект в памяти. Поверхностная копия — spread или Object.assign: верхний уровень новый, вложенные объекты общие. Глубокая копия копирует всё дерево. Современный способ — structuredClone. Старый JSON.parse(JSON.stringify) ломает даты, undefined, функции и Map.

В React это важно: если мутировать старый объект, ссылка та же, и рендер может не увидеть изменение. Правило: не меняй прошлое состояние, собери новое. Обычно хватает spread и замены нужной ветки, а не полного глубокого клона всего стора. На собесе дают два объекта, которые «неожиданно» меняются вместе — это общая ссылка.

Вопрос / ответ

В: Почему после spread вложенный объект всё равно общий?

О: Spread копирует только первый уровень. Внутри остаётся та же ссылка.

16 Map и Set

Object — словарь со строковыми (и symbol) ключами. Map принимает любой ключ, даже объект, и помнит порядок вставки. Set хранит уникальные значения — удобно убрать дубли из массива.

WeakMap и WeakSet держат слабые ссылки: если объект больше нигде не нужен, его заберёт сборщик мусора. Их не перебрать циклом, ключ только объект. На практике WeakMap иногда используют для приватных данных «сбоку» от объекта.

17 Debounce и throttle

Debounce ждёт паузу: функция сработает через N мс после последнего вызова. Так ищут в инпуте: не на каждую букву, а когда человек остановился. Throttle говорит «не чаще чем раз в N мс» — так ограничивают скролл и resize.

Это не методы языка, а приём. В React debounce часто кладут в хук или берут из lodash, и не забывают очистить таймер в useEffect. Если спросят разницу — нарисуй на пальцах: debounce «после тишины», throttle «раз в интервал».

18 Типы данных в TS

TypeScript знает все JS-типы и добавляет свои. Примитивы те же: строка, число, boolean, null, undefined, bigint, symbol. Сверху: any, unknown, never, void, tuple (массив фиксированной длины и состава), enum, literal вроде "admin" | "user". Объект описывают полями, массив — T[].

Типы живут только на проверке. tsc их стирает, в браузере остаётся обычный JS. TS смотрит на форму объекта, а не на «родословную»: подошёл по полям — тип сошёлся. На собесе ждут: примитив vs объект, union vs intersection, tuple vs обычный массив, и чтобы не было any на всё подряд.

Вопрос / ответ

В: Попадают ли типы TypeScript в браузер?

О: Нет. Компилятор их стирает. В рантайме остаётся обычный JavaScript.

19 TypeScript: база

interface описывает форму объекта и умеет мержиться, если объявить дважды. type может описать union, кортеж, примитив — он гибче для комбинаций. Union — «или»: string | number. Intersection — «и»: A & B.

Пропсы компонента обычно кладут в interface. Для функций указывают аргументы и возврат. Если TS «орёт» — чаще прав он, чем ты: значит, данные реально могут быть другими. Middle-уровень: без any, с нормальными пропсами и ответами API.

20 Дженерики

Дженерик — тип-параметр, «коробка T». Функция не знает заранее, что внутри, но обещает: приняла T — вернула T. Так устроены Array<T>, Promise<T>, свой хук useState<User>.

Ограничение пишут через extends: T extends { id: string }. Так можно читать нужные поля и не открывать тип настежь. На собесе могут попросить типизировать функцию identity или обёртку над fetch. Идея одна: не копировать типы вручную, а переиспользовать параметр.

21 any, unknown, never, void

any отключает проверку — это эвакуация, не тип. unknown тоже «что угодно», но сначала нужно сузить проверкой. void — функция ничего полезного не возвращает. never — функция не заканчивается нормально: вечный цикл, throw, невозможная ветка switch.

Если в default у switch стоит never, TS напомнит, когда появится новый вариант union. Для данных с сервера лучше unknown + проверка, чем any. Фраза на собесе: «any — выключатель, unknown — сейф».

22 Utility types

Готовые помощники: Partial<T> делает поля необязательными, Required — обязательными, Pick берёт кусок, Omit выкидывает поля, Record<K, V> — словарь ключ-значение. ReturnType достаёт тип возврата функции.

Их любят, потому что не надо руками дублировать модели. Readonly запрещает запись на уровне типов. Если спросят «как из User сделать форму редактирования» — Partial плюс Pick нужных полей.

23 Архитектуры React: FSD и Atomic

FSD (Feature-Sliced Design) режет проект слоями: app, pages, widgets, features, entities, shared. Фича живёт своей папкой, общее — в shared, нижний слой не знает про верхний. Так проще не превратить проект в свалку components/hooks/utils.

Atomic Design делит UI: атом, молекула, организм, шаблон, страница. Это больше про дизайн-систему и переиспользуемые куски интерфейса, а не про бизнес. FSD отвечает «где лежит фича логина», Atomic — «из каких мелких деталей собрана кнопка». На собесе достаточно сказать: архитектура нужна, чтобы модули имели границы, а не чтобы папки красиво назывались.

24 Стили в React (CSS)

Можно писать обычный CSS/SCSS, CSS Modules, CSS-in-JS (styled-components, emotion) или утилиты вроде Tailwind. Глобальный CSS простой, но классы легко пересекаются между компонентами. Modules на сборке делают имена уникальными — это самый спокойный вариант для больших приложений.

CSS-in-JS удобен, когда стиль зависит от пропсов, но тяжелее бандл и DevTools. Tailwind быстро даёт ровный вид, зато JSX обрастает классами. Инлайн-стили в style={{ }} не умеют псевдоклассы и медиазапросы. На middle ждут: как изолируешь стили и что выберешь для команды, а не «единственно верный способ».

25 Как React работает с DOM

Компонент сам узлы не создаёт и не красит. Он возвращает описание UI. React вызывает функцию, получает новое дерево и сравнивает его со старым. Это ещё не экран: идёт расчёт, что вставить, удалить или поменять. Несколько setState подряд React часто батчит в один проход, чтобы не дёргать DOM по каждому клику.

Потом фаза commit: патч пишется в настоящий DOM. После записи сначала useLayoutEffect — ещё до кадра, им меряют размеры, чтобы не мигнуло. Браузер рисует. Затем useEffect: запросы, подписки, таймеры. В Concurrent Mode расчёт дерева можно прервать и пересчитать. Commit уже трогает DOM, его не прерывают.

1. Render: вызвать компонент, получить новое дерево
2. Reconciliation: сравнить со старым, найти разницу
3. Commit: записать изменения в настоящий DOM
4. useLayoutEffect → кадр на экране → useEffect
Вопрос / ответ

В: Можно ли прервать обновление, когда React уже пишет в DOM?

О: Нет. Render в Concurrent можно поставить на паузу. Commit синхронный: DOM уже меняют.

26 Virtual DOM, reconciliation и Fiber

Virtual DOM — лёгкое JS-описание дерева, не узлы браузера. Сравнивать объекты дешевле, чем сразу трогать настоящий DOM. Reconciliation — алгоритм «что изменилось». React смотрит один уровень, тип элемента и key. Тип сменился с div на span — старое поддерево выкидывают. Ключи стабильные — список не пересоздают целиком.

Fiber — внутренняя архитектура с React 16. Каждый элемент работы — узел Fiber, из них собрано дерево. Работу можно резать на куски: посчитал кусок, отдал кадр браузеру, продолжил. Так вкладка не клинит на большом обновлении. Есть текущее дерево и дерево «в работе»; после commit они меняются местами. У обновлений разный приоритет: ввод важнее, чем тихий пересчёт списка.

Virtual DOM — снимок «как должно выглядеть». Fiber — как React эту работу планирует и ставит на паузу. Скорость не в том, что виртуальное дерево волшебное, а в том, что настоящий DOM трогают точечно и не одной длинной паузой.

Вопрос / ответ

В: Зачем Fiber, если уже есть Virtual DOM?

О: Virtual DOM — описание дерева. Fiber — способ дробить работу, ставить на паузу и не вешать вкладку.

27 Хуки

useState хранит локальное состояние и просит новый рендер. useEffect — побочные эффекты после отрисовки: запрос, подписка, таймер. Если повесил подписку — верни cleanup, иначе будет утечка. useLayoutEffect тот же эффект, но до кадра. useRef держит значение без рендера: DOM-узел, id таймера, прошлый проп.

Правила: только сверху компонента или кастомного хука, не в if и циклах. React помнит хуки по порядку вызова. Сбил порядок — стейт поедет на соседний хук. useMemo кэширует значение, useCallback — функцию. Не мемоизируй всё подряд. Кастомный хук — обычная функция, которая вызывает другие хуки и прячет повтор. Частая ловушка — устаревшее замыкание: эффект захватил старое значение, потому что его нет в зависимостях.

Вопрос / ответ

В: Почему хуки нельзя класть в if?

О: React отличает хуки по порядку. Условие сбивает очередь — значения переедут на чужие хуки.

28 Ключи в списках

key — имя элемента для reconciliation. React не сравнивает «первого с первым по смыслу», он ищет тот же ключ среди соседей. Нашёл — обновил. Не нашёл — создал заново, старый размонтировал вместе со стейтом. Ключ уникален среди братьев, по всему приложению повторяться может.

Лучший ключ — стабильный id с сервера. Индекс годится, только если список не сортируют, не фильтруют и не вставляют в середину. Иначе после перестановки индекс указывает на другого человека, и инпут «переезжает». Случайный ключ ещё хуже: каждый рендер элемент как новый, стейт сбрасывается, фокус прыгает.

Вопрос / ответ

В: Почему нельзя ставить индекс ключом в списке, который сортируют?

О: После сортировки тот же индекс — уже другой элемент. React путает строки, стейт переезжает.

29 Context

Context позволяет отдать данные вниз без пропсов через десять компонентов. Сначала создаёшь контекст, кладёшь Provider, читаешь через useContext. Удобно для темы, локали, текущего пользователя.

Минус: если в value новый объект каждый рендер, обновятся все потребители. Поэтому value мемоизируют или режут контекст на части. Context — не стор: для частых и сложных обновлений лучше Zustand/Redux. На собесе хорошо сказать, когда context уместен, а когда уже нет.

30 Controlled и uncontrolled

Controlled инпут: значение живёт в React-стейте, onChange его обновляет. Источник правды — React, легко валидировать и блокировать кнопку. Uncontrolled: значение сидит в DOM, читаешь через ref, когда надо.

Неконтролируемые поля проще для больших форм и файлов. Нельзя смешивать оба режима на одном инпуте без предупреждения. react-hook-form по сути ближе к uncontrolled: меньше ререндеров на каждый символ.

31 memo, useMemo, useCallback

React.memo не рендерит компонент заново, если пропсы поверхностно те же. useMemo запоминает результат расчёта. useCallback запоминает функцию, чтобы не менялась ссылка и memo-ребёнок не срывался.

Это не ускорители по умолчанию: сравнение пропсов тоже стоит времени. Имеет смысл, когда рендер тяжёлый или компонент часто рендерится из-за родителя. Если в проп уходит объект/массив, созданный на месте, memo не поможет — ссылка каждый раз новая.

32 Сторы: Zustand и Redux

Стор — общее клиентское состояние вне дерева компонентов. Не прокидываешь пропсы через десять уровней и не будишь всё дерево, как часто бывает с Context. В сторе обычно UI: модалки, фильтры, выбранные id. Данные с сервера спокойнее держать в TanStack Query.

Redux Toolkit — строгий поток: компонент диспатчит action, reducer по типу действия возвращает новый state, подписчики обновляются. Есть слайсы, DevTools, middleware. Много церемонии, зато предсказуемо в большой команде. Zustand — маленький хук-стор без провайдера на всё приложение. Пишешь функции прямо в сторе, компонент берёт селектором только свой кусок и ререндерится только от него.

Оба хотят иммутабельности: старый объект не мутируют, отдают новый. В RTK часто помогает Immer, в Zustand тоже можно. На собесе «зачем стор, если есть context»: у стора точечные подписки. Context при новом value будит всех потребителей.

Вопрос / ответ

В: Чем Zustand удобнее Context для частого стейта?

О: Селектор подписывает только на кусок данных. Context при смене value обычно ререндерит всех потребителей.

33 Формы: React, Zod, Yup

Голая React-форма: каждое поле в useState, onSubmit собирает объект. Для средней и большой формы берут react-hook-form: регистрация полей, меньше ререндеров, встроенные ошибки. Yup и Zod — схемы: описал поля один раз, получил валидацию.

Zod дружит с TypeScript: из схемы выводится тип данных, не надо писать интерфейс отдельно. Yup старше и часто встречается в легаси. Типичный связка: схема → resolver → ошибки под инпутами. На собесе ценится фраза: валидация живёт в схеме, а не в куче if внутри onSubmit.

34 TanStack Query и React Router

React Router отвечает за URL: страницы, вложенные роуты, параметры, редиректы, protected routes. TanStack Query (React Query) — кэш серверных данных: статус загрузки, ошибки, повтор, инвалидация. Это не замена Redux. Query для данных с бэка, стор для клиентского UI.

queryKey — адрес кэша, вроде ['user', id]. После мутации вызывают invalidateQueries, чтобы список обновился. Роутер и Query часто встречаются вместе: id из URL → ключ запроса → fetch. На собесе любят вопрос «как не грузить один и тот же профиль дважды» — ответ: общий кэш Query.

35 HTTP базово

Клиент шлёт запрос, сервер отвечает. Методы: GET читать, POST создать, PUT/PATCH обновить, DELETE удалить. Статусы: 2xx ок, 3xx редирект, 4xx ошибка клиента, 5xx ошибка сервера. В запросе заголовки и опционально тело, часто JSON.

HTTP stateless: сервер сам по себе не помнит тебя между запросами, поэтому нужны cookie или токен. На фронте ходят через fetch или axios. HTTPS — тот же протокол, но канал зашифрован. Имеет смысл помнить идемпотентность: повторный GET безопасен, повторный POST может создать вторую запись.

36 CORS

CORS — правило браузера. Страница с одного origin не читает ответ с другого, пока сервер не разрешит. Origin — схема + хост + порт. Поэтому localhost:3000 и localhost:8000 для браузера уже разные миры. Сервер отвечает Access-Control-Allow-Origin и при необходимости разрешает методы, заголовки, cookie.

Простой GET часто идёт сразу. Для «сложного» запроса браузер сначала шлёт preflight OPTIONS: «можно так ходить?». Звёздочка в origin не сочетается с cookie: если нужны credentials, сервер должен назвать конкретный origin. CORS не защита API. Это защита пользователя в браузере. Postman его не проверяет. С фронта честно «починить» нельзя: это бэк или прокси dev-сервера.

Вопрос / ответ

В: Почему в Postman запрос проходит, а из браузера нет?

О: CORS проверяет только браузер. Postman — не страница на чужом origin, ему эти заголовки не нужны.

37 JWT, cookie, Local Storage

JWT — три куска через точку: header, payload, signature. Это не шифр, а подпись: payload можно декодировать, но подделать без секрета сервера нельзя. Фронт криптографию обычно не проверяет, он хранит токен и кладёт в запрос. Короткий access ходит в API. Длинный refresh нужен, чтобы тихо получить новый access, когда старый истёк.

Память JS (переменная, стор в RAM) — скрипт с страницы токен оттуда всё равно видит, пока вкладка жива, но после F5 его нет, и его не прочитать из другой вкладки. Это самый спокойный вариант для access. Local Storage переживает обновление, любой JS на странице его читает — при XSS токен унесут. sessionStorage живёт до закрытия вкладки. HttpOnly cookie JS не видит, браузер шлёт сам: лучше от XSS, но появляется CSRF. Cookie ещё помечают Secure и SameSite.

На собесе не надо клясться одним хранилищем. Скажи плюсы и минусы и что access лучше короткий. Частый взрослый ответ: access в памяти, refresh в HttpOnly cookie.

Вопрос / ответ

В: Почему access не кладут надолго в Local Storage?

О: Любой XSS его прочитает и унесёт. Короткий access в памяти безопаснее, refresh — в HttpOnly cookie.

38 Авторизация на фронте

Логин и пароль фронт шлёт сам: обычно fetch или axios, метод POST, тело JSON, обязательно HTTPS. В адресную строку и query их не кладут — это светится в истории и логах. Сервер отвечает токеном или сам ставит cookie. Дальше к API ходят уже с сессией: либо заголовок Authorization: Bearer, либо браузер сам прикладывает cookie, если запрос с credentials.

Где хранить. Память — лучшее место для короткого access: после F5 его нет, с диска его не вытянуть. Чтобы человек не логинился снова, refresh кладут в HttpOnly cookie. Local Storage берут часто «потому что просто», но при XSS токен унесут. Axios часто вешает interceptor: сам подставляет заголовок и ловит 401. Страницы делят на открытые и закрытые: нет сессии — на логин. Выход — стереть токен и кэш. Фронт пароль не проверяет: он только помнит сессию и прячет UI.

Вопрос / ответ

В: Чем фронт отправляет логин и куда лучше класть токен?

О: POST через fetch или axios, JSON по HTTPS. Access — в память, refresh — в HttpOnly cookie. Так меньше шансов отдать сессию через XSS.

39 XSS и CSRF

XSS — чужой JS на твоей странице: украл токен из Local Storage, нарисовал фейковую форму. Лечится экранированием, не вставлять HTML из пользователя как есть, HttpOnly cookie, CSP. React по умолчанию экранирует текст в JSX, опасно именно dangerouslySetInnerHTML.

CSRF — браузер сам прикладывает cookie к чужому запросу с другого сайта. Лечится SameSite cookie, CSRF-токеном, иногда проверкой Origin. Bearer в заголовке CSRF почти не берёт: чужой сайт не прочитает твой токен из JS. Поэтому связка «access в памяти + refresh в HttpOnly cookie» часто звучит как взрослый ответ.

40 Box model, Flex, Grid

У блока есть content, padding, border, margin. С box-sizing: border-box ширина включает padding и border — так живут почти все современные вёрстки. Flex — одно направление: ряд или колонка, выравнивание, распределение свободного места. Grid — двумерная сетка: и строки, и колонки сразу.

Flex берут для шапки, кнопок, списка карточек в ряд. Grid — для раскладки страницы и галерей. gap заменяет большинство margin между детьми. На собесе могут попросить сверстать шапку: логотип слева, меню справа — это flex и space-between.

41 Позиционирование

static — обычный поток. relative сдвигает относительно себя, якорь для absolute-детей. absolute вынимает из потока и позиционирует от ближайшего не-static предка. fixed липнет к окну, sticky ведёт себя как relative, пока не доскроллишь — потом как fixed.

Боковое меню этой страницы — sticky. Модалка часто fixed на весь экран. z-index работает только у позиционированных элементов. Если «элемент уехал непонятно куда» — почти всегда ищут, у какого родителя position не static.

42 Когда вбиваем домен в строку — что дальше?

Браузер понимает: это URL, а не поисковый запрос. Разбирает схему, домен, путь. Потом ищет IP: кэш браузера → кэш ОС → DNS. Имя сайта само по себе в сеть не ходит, нужен адрес машины.

TCP открывает надёжный канал до этого IP и порта. Сначала рукопожатие из трёх шагов: «привет» (SYN), «принял, вот и я» (SYN-ACK), «ок, работаем» (ACK). После этого байты идут по порядку, потерянное просят ещё раз. Это ещё не шифр и не сайт, только труба.

TLS надевается на эту трубу, если схема https. Браузер проверяет сертификат: тот ли это сайт и доверяем ли мы тому, кто подписал. Потом стороны договариваются о ключах и дальше шифруют трафик. HTTP после этого становится HTTPS: тот же запрос-ответ, но его не прочитать по дороге. Затем уходит HTTP-запрос, приходит HTML, браузер тянет CSS и JS и рисует страницу.

1. Разобрать URL: схема, домен, путь
2. DNS: имя сайта → IP
3. TCP: рукопожатие, надёжный канал
4. TLS: сертификат + шифрование
5. HTTP: запрос → HTML и ресурсы → отрисовка
Вопрос / ответ

В: Зачем TLS, если уже есть TCP?

О: TCP только доставляет байты по порядку. TLS шифрует их и проверяет, что ты на нужном сайте, а не у перехватчика.

43 Как из HTML получаются пиксели?

Браузер читает HTML и строит DOM, читает CSS и строит CSSOM. Из них собирается render tree: только то, что реально видно. Потом layout считает размеры и координаты, paint рисует пиксели, composite склеивает слои.

JS может остановить разбор HTML, если скрипт без async/defer стоит в середине. CSS тоже блокирует отрисовку: без стилей браузер не хочет показывать «голую» страницу. На собесе это зовут critical rendering path — путь от байтов до первого кадра.

44 Что происходит, когда в React кликаем кнопку?

Браузер ловит click и отдаёт его обработчику в JSX. Там обычно вызывают setState / сеттер из useState. React не сразу лезет в DOM: он планирует новый рендер компонента.

Компонент вызывается снова, получается новое дерево, React сравнивает его со старым и точечно обновляет DOM. Потом эффекты: сначала useLayoutEffect, кадр на экране, потом useEffect. Если стейт не изменился, лишней работы может и не быть.

45 Что происходит при переходе по роуту?

В SPA клик по Link не перезагружает страницу. React Router меняет URL через History API и выбирает другой компонент для этого пути. Старая страница размонтируется, новая монтируется, DOM обновляется кусками.

Данные часто грузятся уже после смены экрана: useEffect или TanStack Query по id из URL. Сервер при таком клике новый HTML не отдаёт — он уже отдал приложение один раз. Если человек нажмёт F5, вот тогда браузер снова сходит за HTML по этому адресу, и бэк должен уметь отдать SPA, а не 404.

46 Что происходит при F5 на странице с авторизацией?

Память JS обнуляется: переменные, стейт React, стор в RAM. Браузер заново качает HTML и бандл. Если токен лежал только в переменной — его нет, человека выкинет на логин. Если он в Local Storage или cookie — приложение при старте читает его и снова ходит в /me.

Поэтому «остаться в системе после обновления» — это про хранение сессии, а не про магию React. Короткий access мог истечь: тогда фронт берёт refresh и тихо получает новый. На собесе это хороший мостик к теме JWT vs cookie.

47 Module

Модуль прячет внутренности и отдаёт наружу только нужное. В JS это файл с export: снаружи видно то, что ты сам открыл. Раньше тот же приём делали замыканием. На фронте так живут утилиты, API-клиент, конфиг.

Смысл не в папках, а в границе: не светить лишние детали и не плодить глобальные переменные. Если на собесе спросят «как спрятать приватные данные» — модуль плюс замыкание.

48 Singleton

Синглтон — один экземпляр на всё приложение. Стор Redux или Zustand по сути такой: одно общее состояние. Тема, текущий пользователь, клиент API часто тоже живут в одном экземпляре.

Плюс: все ходят в одну точку и видят одни данные. Минус: тестировать сложнее, легко превратить в свалку. На собесе хватит фразы: «один объект, к нему ходят отовсюду».

49 Observer / Pub-Sub

Наблюдатель: кто-то изменился — подписчики узнали, без прямой связи. В React так работают стейт, контекст и стор: подписался компонент — получил обновление. События DOM — тот же паттерн.

Pub-sub чуть свободнее: есть канал вроде «пользователь вошёл», кто хочет — слушает. Главное слово на собесе — слабая связанность: отправитель не знает список слушателей.

50 Factory

Фабрика — функция, которая создаёт объект или компонент по условию. Снаружи не размазываешь кучу if: «дай мне кнопку нужного типа». createElement в React — фабрика элементов.

Удобно, когда видов много, а создавать их хочется одинаково. На собесе могут спросить «как не писать switch на каждый тип карточки» — ответ: фабрика или словарь компонент по типу.

51 Strategy

Стратегия — подменяемый алгоритм с одним интерфейсом. Валидация формы, сортировка таблицы, способ оплаты: снаружи один вызов, внутри разная логика. В React часто просто передают функцию пропом.

Отличие от каши из if: новый вариант — новая стратегия, старый код почти не трогаешь. Если спросят разницу с фабрикой: фабрика создаёт объект, стратегия меняет поведение уже в работе.

52 Adapter

Адаптер переводит чужой формат в свой. Бэк отдал неудобные поля и даты-строки — адаптер делает модель, с которой удобно рисовать UI. Или обёртка над старой библиотекой, чтобы говорить с ней как с новой.

На фронте это почти всегда маппинг ответа API. Компонент не должен знать, как бэк назвал поле. На собесе: «между сервером и UI стоит переводчик».

53 Decorator и HOC

Декоратор оборачивает объект и добавляет поведение, не меняя оригинал. В React это был HOC: withAuth, withTheme — функция принимает компонент, возвращает обёрнутый. Сейчас чаще кастомные хуки и компоненты-обёртки.

Идея та же: не копировать логику, а надеть сверху. Минус HOC — ад обёрток и путаница с пропсами. Если спросят «чем заменить HOC» — хук или обёртка через children.

54 Facade

Фасад — простая дверца к сложной кухне. Вместо трёх fetch, заголовков и разбора ошибок из компонента есть один вызов вроде «дай пользователя». Компонент не знает про HTTP.

Так обычно держат клиент бэка. На собесе: «спрятал сложность за одним простым методом». Не путать с адаптером: фасад упрощает вход, адаптер меняет форму данных.

55 Композиция

React почти не про наследование классов. Композиция — собрал UI из маленьких частей, как лего: children, слоты, кастомные хуки. Большой экран = набор мелких компонентов, а не длинная цепочка extends.

Наследование жёстко связывает, композиция гибче. Фраза, которую ждут: «не наследуй кнопку, оберни её или передай children». Это главный паттерн фронта, даже если его не называют словом из книжки.

56 MVC

MVC: Model — данные, View — картинка, Controller — связка. Так учили классику. React сам по себе не чистый MVC: компонент часто и view, и кусок контроллера, данные живут в стейте или сторе.

MVVM ближе к «данные сами связаны с UI». На собесе не надо впихивать React в эти буквы. Достаточно сказать: знаю слои, но в React думаем компонентами и односторонним потоком данных, а не жёстким MVC.
